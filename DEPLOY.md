# Размещение на GitHub и Railway

## Сервисы

Создайте в одном Railway Project:

1. PostgreSQL;
2. `web`: `npm run start`, health check `/api/health`;
3. `worker`: постоянный процесс обработки `SyncJob`;
4. Cron: короткие команды-планировщики, которые только создают задания.

Railway Cron не подходит как единственный механизм длинной синхронизации: задания маркетплейсов используют пагинацию, ожидание готовности отчётов, `Retry-After` и восстановление после сбоя. Постоянный worker хранит состояние в PostgreSQL и безопасно продолжает работу.

## Порядок

1. Создайте приватный GitHub-репозиторий и отправьте код без `.env`.
2. Подключите репозиторий к Railway.
3. Добавьте переменные из `.env.example` через Railway Variables.
4. Выполните production-миграцию `npx prisma migrate deploy`.
5. Соберите `npm run build` и запустите web/worker.
6. Привяжите домен, проверьте HTTPS и callback URL OAuth.
7. Настройте автоматический backup PostgreSQL и выполните тестовое восстановление.

## Рекомендуемое расписание старта

- заказы — каждые 30 минут;
- остатки — каждый час;
- продажи и реклама — каждые 3 часа;
- финансы и снимки остатков — ежедневно;
- перекрывающее обновление последних 7–30 дней — по политике конкретного источника.

Расписание включается только после live-проверки лимитов конкретного кабинета.
