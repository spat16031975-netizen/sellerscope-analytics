# Модель данных

Полная схема находится в `prisma/schema.prisma`.

## Граница арендатора

`Organization` — корень данных клиента. `Membership` связывает пользователя с организацией и ролью. Магазин всегда принадлежит одной организации. Сервер получает `organizationId` из проверенной сессии, а не доверяет значению из URL. Запросы к дочерним сущностям начинаются с фильтра организации либо проходят через принадлежащий ей `Store`.

## Основные сущности

- `Store` — кабинет/магазин одной площадки;
- `Connection` — отдельный WB Seller, WB Promotion, Ozon Seller или Ozon Performance доступ;
- `Product` — внутренний SKU организации;
- `StoreProduct` — внешний идентификатор товара на конкретной площадке;
- `SkuMapping` — ручное подтверждённое соответствие SKU;
- `Order`/`OrderItem` — факт размещения заказа;
- `SaleEvent` — продажа, возврат или корректировка;
- `FinanceOperation` — начисление/удержание с типом и исходным ID;
- `AdCampaign`/`AdStat` — реклама и атрибуция площадки;
- `StockSnapshot` — раздельные available/reserved/inTransit/returning;
- `CostEntry` — себестоимость с периодом действия;
- `Plan`, `AlertRule`, `Alert` — планирование и сигналы;
- `SyncJob` — курсор, попытки, окно и результат синхронизации;
- `AuditEvent` — важные действия пользователей и системы.

## Идемпотентность

У каждой входной записи есть уникальность по магазину, source ID и типу события. `SyncJob.idempotencyKey` запрещает параллельный дубль одного окна. Обновление выполняется через upsert; временно пустой ответ не удаляет историю.

## Версионирование преобразований

Каждая нормализованная запись хранит `transformVersion`, `fetchedAt`, исходное время, валюту и `raw`. При изменении схемы коннектора можно повторно преобразовать raw-данные и сравнить результат.
