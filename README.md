# SellerScope Analytics

SellerScope Analytics — личный дашборд продавца Wildberries и Ozon. Репозиторий содержит единый адаптивный итоговый лист, раздельный выбор магазина, локальный импорт отчётов CSV/JSON/XLSX, доменную модель PostgreSQL/Prisma и тесты расчётов.

## Что уже работает

- восемь разделов на одной прокручиваемой странице; боковая и мобильная навигация работают как оглавление;
- переключение между Ozon и Wildberries без смешивания данных;
- два пути получения аналитики: локальный импорт CSV/JSON/XLSX или проверяемое сервером подключение API;
- адаптеры отчётов Ozon: заказы, аналитика по товарам, каталог/остатки и продвижение;
- отдельные представления заказов, реализаций, возвратов и финансов;
- пустой шаблон с честными нулевыми значениями до загрузки отчёта;
- состояния неполных данных без вымышленных показателей;
- журнал уведомлений, который заполняется после анализа данных;
- единый выбранный дизайн Finance Bento;
- документированные формулы и источники;
- Prisma-модель для организаций, пользователей, магазинов, подключений, продаж, рекламы, остатков и синхронизаций;
- контракт четырёх независимых коннекторов;
- автоматические тесты безопасного деления и межклиентской изоляции.

## Что намеренно не объявлено готовым

- реальные подключения не проверены без разрешённых кабинетов продавцов;
- OAuth Ozon и шифрование учётных данных спроектированы, но ещё не подключены к production key management;
- worker синхронизации и production-авторизация являются следующим инкрементом;
- Репозиторий GitHub создан; production-размещение на Railway пока не настроено.
- визуальный browser QA итогового листа выполнен на локальном URL, включая мобильную компоновку и якорную навигацию.
- API-ключи не сохраняются в браузере или Git; текущий прототип проверяет соединение, а постоянная фоновая синхронизация потребует зашифрованного production-хранилища.

## Рекомендуемая архитектура

Один репозиторий, но два Railway-процесса: `web` обслуживает Next.js и API, `worker` забирает задания из PostgreSQL и выполняет синхронизации. Railway Cron только добавляет задания в очередь; длинные выгрузки, повторы и ожидание `Retry-After` выполняет постоянный worker. Это предотвращает наложение запусков и потерю состояния при перезапуске.

Дата аудита API: **17 ноября 2026 года**.

## Известный риск зависимости

`npm audit` сообщает high advisory в `deepmerge-ts`, который приходит через конфигурационный пакет Prisma CLI 6.19.3. Уязвимость относится к рекурсивному слиянию недоверенных конфигурационных объектов; SellerScope не принимает Prisma-конфигурацию от пользователей. Тем не менее перед production-релизом Prisma следует обновить до исправленной major-версии после отдельной миграционной проверки.
